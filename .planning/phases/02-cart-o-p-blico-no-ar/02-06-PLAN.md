## Phase Goal

**As a** dono de um cartão digital, **I want to** ter meu cartão acessível publicamente em `/[slug]` e um QR pronto para circular, **so that** qualquer pessoa que escaneie ou receba o link veja meu cartão carregando rápido, sem cadastro e sem espera.

<objective>
Fecha a fase: o produto ganha endereço próprio. O `apps/web` sobe na Vercel, o domínio registrado no plano 02-05 passa a apontar para ele, e `NEXT_PUBLIC_APP_URL` finalmente recebe o valor real — o que faz todo QR já gerado codificar a URL definitiva, sem nenhuma mudança de código (foi exatamente por isso que D-15 proibiu hardcode).

Purpose: `BRAND-01` era a pendência bloqueante registrada no `PROJECT.md` desde o início ("o produto não tem nome nem domínio"). Enquanto ela existir, não há URL para imprimir num adesivo nem para compartilhar. Este plano também é o único ponto da fase em que o caminho completo — visitante → edge da Vercel → Render → Neon — é exercitado com infraestrutura real e fria, que é a hipótese mais arriscada do projeto segundo `research/ARCHITECTURE.md`.

Output: frontend em produção no domínio próprio, CORS de produção corrigido, runbook atualizado com o estado real e verificação end-to-end de todos os requisitos da fase em produção.
</objective>

Estrutura do repositório: monorepo com `apps/web` (Next.js 16.3.1) e `apps/api` (.NET 10). Na Vercel, o **Root Directory** do projeto deve ser `apps/web`.

Variáveis lidas pelo `apps/web` em produção:
- `NEXT_PUBLIC_API_URL` — consumida por `lib/api-client.ts` (browser, dashboard autenticado) e por `lib/public-card.ts` (servidor, Server Component da página pública). Recebe a URL do Render.
- `NEXT_PUBLIC_APP_URL` — consumida por `lib/qr.ts` (`buildCardUrl`) e, por reuso, por `lib/prewarm.ts`. Recebe `https://{dominio}`.
- `BLOB_READ_WRITE_TOKEN` — server-only, consumida por `app/api/upload/route.ts` (Fase 1).

`apps/api/Program.cs` usa `policy.WithOrigins(webOrigin)` com **origem única** vinda de `Cors__WebOrigin`. Trocar o domínio do frontend exige atualizar essa variável no Render e redeployar — senão as chamadas do dashboard autenticado (que são browser-side, via `apiFetch`) passam a ser bloqueadas pelo navegador. A página pública **não** é afetada por isso: o fetch dela sai do servidor da Vercel, e CORS é enforcement de browser (`02-RESEARCH.md` Pattern 3).

Mecânica de DNS da Vercel (docs oficiais, `02-RESEARCH.md`): domínio apex (`vizzo.com.br`) usa registro **A**; subdomínio (`www.vizzo.com.br`) usa **CNAME**. Os valores exatos são exibidos pela Vercel ao adicionar o domínio — usar os que ela indicar, não valores memorizados.

Limite relevante da Vercel: funções no plano Hobby rodam até 60s (Fluid Compute), o que cobre com folga o pior caso de Render frio (~30-60s) somado ao wake do Neon (~500ms) — nenhum ajuste de `maxDuration` é necessário.

Do plano 02-05 vieram, registrados no SUMMARY: a URL pública do Render e o domínio efetivamente registrado.

`apps/web/vitest.config.ts`, `apps/web/next.config.ts` e o código da aplicação **não** devem ser alterados por este plano — a troca de domínio é inteiramente de configuração, e isso é o teste de que D-15 foi respeitado.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DNS público → Vercel Edge | Resolução e terminação de TLS acontecem antes de qualquer código da aplicação rodar |
| Browser do dono (domínio novo) → Render | Chamadas autenticadas do dashboard agora saem de uma origem diferente, sujeitas à política de CORS |
| Vercel Edge → Render | Chamada server-to-server da página pública, sem CORS e sem credenciais |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-25 | Elevation of Privilege | `Cors__WebOrigin` no Render | mitigate | Valor deve ser a origem exata `https://{dominio}` — nunca `*`, nunca lista aberta, nunca deixar a URL `*.vercel.app` antiga acumulada; `Program.cs` aceita origem única por construção, então o gate é a Task 1 passo 6 mais o registro do valor final no SUMMARY |

Se apex e `www` coexistirem, uma delas deve redirecionar para a canônica, evitando duas origens válidas para a mesma aplicação |
