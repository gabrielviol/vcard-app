# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this phase's UI:** register/login screens, dashboard shell, and the single-screen card editor (identity, contact, Pix, social links sections) — per D-01/D-03. No public card page, no QR, no `.vcf` — those are Phase 2/3.

**Note on shadcn state:** `apps/web` does not exist yet (this project is greenfield — confirmed via repo scan, no `components.json`, no Tailwind config, no `apps/` directory). shadcn cannot be initialized into a non-existent Next.js project. The preset below is **locked and confirmed** by the user; the executor must run `npx shadcn init` with this exact preset as the first UI-related step of Phase 1 Wave 0 (after `apps/web` is scaffolded per `docs/specs/01-setup.md`), then set `shadcn_initialized: true` in this file's frontmatter.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | New York style, Zinc base color, CSS variables enabled — confirmed by user, not yet executed (see note above) |
| Component library | Radix UI (via shadcn primitives) |
| Icon library | lucide-react (shadcn default) |
| Font | Geist Sans (Next.js/shadcn default, via `next/font`) — covers Latin Extended-A (ã, õ, ç, á, é) needed for Brazilian names; body text only in this phase, no OG image rendering yet |

**Required shadcn blocks for this phase** (install during Wave 0, after init):
`button`, `input`, `label`, `form`, `card`, `dialog`, `checkbox`, `select`, `avatar`, `separator`, `sonner`, `badge`

Not covered by shadcn (custom/third-party, non-registry):
- Drag-to-reorder for social links (CARD-10) — no shadcn primitive; use a lightweight DnD library (e.g. `@dnd-kit/sortable`) wrapping the `card`/list rows. Not a registry safety concern (not a shadcn registry block), but flag as a new dependency for the planner to vet like any other package.
- WhatsApp mask input — `react-imask` (already selected in RESEARCH.md), wraps the shadcn `input` component, not a registry block.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (mask hint text below WhatsApp field, Pix preview line) |
| md | 16px | Default element spacing (form field vertical rhythm) |
| lg | 24px | Section padding (identity / contact / Pix / social-links section blocks) |
| xl | 32px | Layout gaps (space between the 4 form sections) |
| 2xl | 48px | Major section breaks (login/register card padding, page header to first section) |
| 3xl | 64px | Page-level spacing (top/bottom page margins on desktop) |

Exceptions:
- **44px minimum touch target** on all icon-only interactive elements: drag handle (social link reorder), "Remover" icon button on social link rows, "Remover foto" icon button — mobile-first constraint from CLAUDE.md applies even though this phase is dashboard-only, since the dono may edit from a phone.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage:
- **Display (28px):** page-level titles — "Criar seu cartão" / "Entrar" / "Criar conta"
- **Heading (20px):** section titles within the card editor — "Identidade", "Contato", "Pix", "Links sociais"
- **Label (14px/600):** form field labels, helper/hint text under fields (WhatsApp normalized preview, Pix formatted preview)
- **Body (16px/400):** input text, paragraph copy, empty-state body text

Only 2 weights declared (400, 600) — no third weight introduced anywhere in this phase's UI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `zinc-50` (#FAFAFA) background / white cards | Page background, form card background |
| Secondary (30%) | `zinc-100` / `zinc-200` (#F4F4F5 / #E4E4E7) | Input borders, section dividers, sidebar/nav background, disabled states |
| Accent (10%) | `indigo-600` (#4F46E5) | Reserved for: primary CTA buttons ("Criar cartão", "Salvar alterações", "Entrar", "Criar conta"), active nav item indicator, focus rings on inputs, real-time slug-availability "disponível" success indicator |
| Destructive | `red-600` (#DC2626) | "Remover" text/icon buttons (social link row, remove photo), form validation error text and borders, CPF Pix warning modal's risk framing text |

Accent reserved for: primary action buttons, active nav state, input focus ring, slug-availability success check — never for illustrative icons, decorative elements, or secondary/tertiary buttons ("Cancelar" uses secondary/ghost style, not accent).

No WhatsApp-green or Pix-brand colors used in this phase's UI — that visual language is reserved for the public card (Phase 3), confirmed by user.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (create card) | "Criar cartão" |
| Primary CTA (save edits) | "Salvar alterações" |
| Primary CTA (login) | "Entrar" |
| Primary CTA (register) | "Criar conta" |
| Empty state heading (no social links yet) | "Nenhum link ainda" |
| Empty state body (no social links yet) | "Adicione Instagram, LinkedIn ou outro link para aparecer no seu cartão." |
| Error state (generic save failure) | "Não foi possível salvar. Verifique sua conexão e tente novamente." |
| Error state (slug taken) | "Esse link já está em uso. Escolha outro." |
| Error state (invalid Pix key, by type) | "CPF inválido." / "CNPJ inválido." / "E-mail inválido." / "Telefone inválido." / "Chave aleatória inválida." (per CARD-06, mirrors `cpf-cnpj-validator` / regex validation results) |
| Destructive: remove social link | Inline "Remover" per row, no confirmation modal (low-stakes, reorderable list, no permanent data loss — link can be re-added) |
| Destructive: remove photo | Inline "Remover foto", no confirmation modal (re-uploadable, no data loss) |
| Destructive confirmation: CPF as Pix key (blocking, per D-09/CARD-07) | Modal — "Sua chave Pix é seu CPF. Isso significa que seu CPF ficará visível para qualquer pessoa que acessar seu cartão." + checkbox "Confirmo que quero usar meu CPF como chave Pix." — "Confirmar" button disabled until checkbox is checked |
| Pix exposure notice, low-risk types (email/telefone/aleatoria, per D-08) | Inline text below field, non-blocking: "Essa chave ficará visível publicamente no seu cartão." |
| Session expiry (401 redirect, per D-06) | On redirect to `/login`: "Sua sessão expirou. Entre novamente." |
