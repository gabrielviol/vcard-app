<!-- Contratos vindos do plano 01. Não precisa explorar o backend para descobrir. -->

`POST /auth/register` e `POST /auth/login` recebem `{ email, password }` e retornam `{ accessToken, user: { id, email } }` (201 / 200).
`POST /auth/register` retorna 409 `{ error: "email_taken" }` se o e-mail já existe.
`POST /auth/login` retorna 401 `{ error: "invalid_credentials" }` para credencial inválida (mensagem idêntica para e-mail inexistente e senha errada).
`GET /auth/me` exige `Authorization: Bearer {token}` e retorna `{ id, email }`; 401 sem token válido.
Base URL da API vem de `NEXT_PUBLIC_API_URL` (local: `http://localhost:5000`, ajustar para a porta real do `launchSettings.json` gerada no plano 01).

Contratos criados aqui e consumidos pelos planos 03-07:
- `lib/auth-storage.ts` exporta `getToken(): string | null`, `setToken(token: string): void`, `clearToken(): void`, com a chave de storage `accessToken`.
- `lib/api-client.ts` exporta `apiFetch<T>(path: string, init?: RequestInit & { auth?: boolean }): Promise<T>` — injeta `Authorization: Bearer` quando `auth` não é `false`, faz `JSON.parse` da resposta, e lança `ApiError { status, code, message }` em respostas não-OK. Em `status === 401` limpa o token e navega para `/login?expired=1` antes de lançar.
</interfaces>
