## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Worktree torn down mid-checkpoint | An executor agent reached a blocking checkpoint, returned its report, and the harness removed its worktree before it could be resumed via SendMessage (`work-tree-elsewhere` error). | advisory | Before respawning, always verify `git log <base>..<worktree-branch>` is empty (no lost commits) before deleting the stray branch and starting a fresh executor. In this session it was empty both times — no data was lost — but always check first. |
| docker-compose port conflict from prior executor | A worktree executor's own `docker compose up -d db` (project name derived from its worktree path) leaves a Postgres container bound to host port 5432 running even after the worktree is deleted. The orchestrator's own `docker compose up -d db` (project name `vcard-app`) then fails with "port is already allocated". | advisory | Run `docker ps -a` first; if a healthy `*-db-1` container already holds 5432, reuse it directly for build/test gates instead of fighting it. Only `docker compose up -d db` if nothing is already listening on 5432. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.


1. Open `http://localhost:3000` → should redirect to `/login`
2. Go to `/register`, create an account (8+ char password) → should land on `/dashboard` showing your e-mail
3. Press F5 on `/dashboard` → stays logged in, no loading flash
4. DevTools → Application → Local Storage → confirm `accessToken` key exists
5. Delete `accessToken`, reload → immediate redirect to `/login`
6. Log in with the same account → back to `/dashboard` with correct e-mail
