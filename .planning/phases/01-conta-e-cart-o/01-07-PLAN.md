<!-- Contratos deste slice -->

Plataformas aceitas (valores persistidos em `social_links.platform`, minúsculos): `instagram`, `linkedin`, `twitter`, `tiktok`, `youtube`, `site`.

DTOs (`apps/api/Contracts/SocialLinkDtos.cs`):
- `SocialLinkWriteDto(string Platform, string Url)`
- `SocialLinkResponseDto(Guid Id, string Platform, string Url, int DisplayOrder)`
- `SocialLinkOrderDto(Guid[] OrderedIds)`

Endpoints (todos com `.RequireAuthorization()` e checagem de posse do cartão):
- `POST /cards/{cardId}/social-links` → 201 `SocialLinkResponseDto` | 400 `{ error: "platform_invalid" }` | 400 `{ error: "url_invalid" }` | 403 `{ error: "not_owner" }`
- `DELETE /cards/{cardId}/social-links/{linkId}` → 204 | 403 `not_owner` | 404
- `PUT /cards/{cardId}/social-links/order` recebendo `SocialLinkOrderDto` → 200 com a lista reordenada | 400 `{ error: "order_mismatch" }` quando os ids enviados não correspondem exatamente ao conjunto de links do cartão | 403 `not_owner`

Regra de URL: somente `https` absoluto (esquemas `javascript:`, `data:`, `http:` recusados) e comprimento máximo de 500 caracteres. `display_order` é reatribuído como índice sequencial começando em 0 a cada reordenação e a cada remoção — nunca deixa buracos.

`GET /cards/me` (plano 03) já devolve `SocialLinks` ordenados por `display_order`; nenhuma mudança nesse contrato.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → endpoints de SocialLink | `platform`, `url` e o array de ids de ordenação são entrada não confiável |
| `social_links.url` → página pública (Fase 2) | O valor gravado vira `href` numa página pública, clicável por qualquer visitante |
| `linkId` na rota → posse | Um id de link não carrega informação de dono; a posse precisa ser derivada do cartão |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-38 | Elevation of Privilege | `POST`/`DELETE`/`PUT order` de SocialLink (BOLA) | mitigate | Cada handler carrega o cartão por `cardId` e compara `card.UserId` com a claim `sub` antes de qualquer escrita; `DELETE` ainda confere que o `linkId` pertence àquele `cardId`, fechando o caso de id válido em cartão alheio (ASVS V4) |
| T-01-39 | Tampering | XSS armazenado via `url` do link (`javascript:`/`data:`) | mitigate | `IsValidUrl` aceita somente URI absoluta com esquema exatamente `https`, com teste explícito rejeitando `javascript:alert(1)` — é a mitigação que protege a página pública da Fase 2, onde esse valor vira `href` |
| T-01-40 | Tampering | Plataforma arbitrária gravada | mitigate | Allow-list de 6 valores com comparação case-insensitive; qualquer outro valor recebe 400 `platform_invalid`, impedindo que a Fase 2 tente resolver um ícone/rota inexistente |
| T-01-41 | Tampering | Reordenação com ids de outro cartão | mitigate | `PUT .../order` compara o conjunto recebido com o conjunto de ids do cartão e recusa com 400 `order_mismatch` se divergir — impede escrita cruzada disfarçada de reordenação |
| T-01-42 | Denial of Service | Criação ilimitada de links | accept | Superfície autenticada, um cartão por usuário, e a lista é visualmente autolimitante no MVP; limite rígido pode entrar quando houver sinal de abuso real |
| T-01-43 | Information Disclosure | Links sociais são públicos por natureza | accept | É o propósito do campo — o dono escolhe o que publica |
</threat_model>
